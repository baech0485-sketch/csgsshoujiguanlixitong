# 员工分配与离职回收流程设计

**目标**

将“手机资产入库 -> 员工管理 -> 手机分配 -> 审批确认 -> 员工领用签字 -> 离职回收 -> 手机回库待分配”串成一条完整闭环，所有关键节点都写入云数据库，可追溯、可核对、可回看签字结果。

## 一、业务范围

本次范围覆盖以下 4 个后台页面与 2 个员工移动端确认页面：

1. 员工管理
2. 领用分配
3. 审批中心
4. 离职回收
5. 员工领用确认链接页
6. 员工离职归还确认链接页

手机资产页面继续作为公司所有手机统一入库页面，不负责分配员工，只负责资产建档、查看和维护。

## 二、核心口径

### 1. 员工唯一标识

- 页面展示：`员工姓名`
- 系统唯一键：`员工编号`
- 组合展示：`员工编号 + 姓名`

### 2. 员工状态

- `在职`
- `离职`

只有 `在职` 员工可以被手机分配页面选中。离职员工在分配页面必须被排除。

### 3. 手机状态

本次统一采用以下状态：

- `在库`：新录入或暂未进入使用流程
- `待分配`：回收完成后重新进入可分配池
- `待领取`：资产管理员已分配给员工，等待员工确认
- `使用中`：员工已确认领取并签字
- `待回收`：员工进入离职回收流程，等待员工确认归还

`在库` 与 `待分配` 都可被领用分配页面选中。

### 4. 确认链接机制

- 后台生成一条带随机 `token` 的公开确认链接
- 员工不需要登录后台账号
- 员工打开链接后可查看本次待确认内容
- 员工必须完成手写签字后才能提交
- 签字内容以图片数据与签字时间一起写入云数据库

## 三、完整流程

### 流程 A：手机分配与领取

1. 资产管理员先在“手机资产”中录入手机并入库
2. 管理员在“员工管理”中录入员工，员工状态默认为 `在职`
3. 管理员进入“领用分配”页面
4. 从可分配手机中选择一台手机
5. 从员工管理数据中选择一个 `在职` 员工
6. 提交后系统执行：
   - 更新手机责任人为该员工
   - 手机状态改为 `待领取`
   - 自动生成一条审批记录
   - 自动生成员工领取确认链接
7. “审批中心”会出现这条分配记录，并展示：
   - 员工信息
   - 手机信息
   - 当前状态
   - 确认链接
8. 员工打开链接，在手机上核对设备信息
9. 员工手写签字并点击确认
10. 系统执行：
    - 审批记录写入签字图片、签字时间
    - 审批状态更新为 `已领取`
    - 手机状态更新为 `使用中`

### 流程 B：离职回收

1. 人员离职前，管理员进入“离职回收”
2. 选择一个员工
3. 系统自动展示该员工名下所有手机
4. 管理员发起回收流程后，系统执行：
   - 生成离职回收单
   - 手机状态更新为 `待回收`
   - 生成员工归还确认链接
5. 员工打开手机链接，查看本次需要归还的全部设备
6. 员工确认已归还全部设备，并完成在线签字
7. 系统执行：
   - 回收单写入签字图片、签字时间
   - 对应手机全部解除责任人
   - 手机状态改为 `待分配`
   - 员工状态改为 `离职`
   - 离职回收单状态更新为 `已回收`

## 四、页面要求

### 1. 员工管理

- 列表展示：员工编号、姓名、部门、手机号、岗位、状态、在管手机数量
- 支持新增员工
- 支持切换员工状态
- 支持搜索员工编号/姓名
- 支持查看该员工名下手机数量

### 2. 领用分配

- 页面不再以“审批通过任务”驱动
- 页面以“设备 + 员工”直接创建分配记录
- 可选设备来源：`在库`、`待分配`
- 可选员工来源：员工管理中 `在职` 员工
- 成功分配后要立即展示生成的确认链接

### 3. 审批中心

- 重点展示分配确认记录
- 每条记录展示：
  - 员工编号、姓名
  - 分配手机编号与型号
  - 当前状态
  - 生成的确认链接
  - 员工签字状态
  - 签字时间
- 若员工已签字，需展示签字预览或下载入口

### 4. 离职回收

- 选择员工后自动带出名下手机
- 发起回收后展示回收链接
- 展示回收状态、签字状态、签字时间
- 归还完成后可见“已回收入库，待再次分配”的状态结果

### 5. 移动端领取确认

- 通过 `token` 直接访问
- 展示员工信息、手机信息、确认清单
- 提供手写签字区域
- 需勾选确认项后才能提交

### 6. 移动端离职归还确认

- 通过 `token` 直接访问
- 展示本次需归还的全部手机
- 提供手写签字区域
- 提交后一次性完成全部设备的回收确认

- `phone`
- `title`
- `status`
- `deviceCount`
- `createdAt`

## 六、默认实现假设

当前默认采用以下实现口径，除非后续你明确要求修改：

- 签字使用网页画布手写签字
- 签字结果以 Base64 图片形式存库
- 确认链接使用项目公网根地址或本地地址拼接
- 员工领取确认和离职归还确认均无需登录，仅校验 `token`
- 一个分配记录只绑定一台手机
- 一个离职回收单可以绑定多台手机

## 七、导航调整

后台左侧导航顺序调整为：

1. 仪表盘
2. 手机资产
3. 员工管理
4. 领用分配
5. 审批中心
6. 离职回收
7. 异常管理

## 八、验收标准

- 手机只能先入库，再在领用分配页面分配
- 离职员工不能被再次分配手机
- 领用分配后审批中心必须自动出现该条记录
- 审批中心必须能看到确认链接与签字结果
- 员工领取确认后，手机状态必须更新为 `使用中`
- 离职回收后，手机状态必须更新为 `待分配`
- 离职回收完成后，员工状态必须更新为 `离职`
- 所有关键节点必须写入云数据库
